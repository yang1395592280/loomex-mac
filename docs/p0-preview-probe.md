# P0 / T0.4 自建窗口预览与降级

日期：2026-11-07。状态：纯状态测试 30/30、构建签名、无权限图标降级、自建样本选择，以及获准后的单次真实截图和释放已通过。本机 macOS 27.0 / Xcode 27.2；该原型不是产品窗口服务，T0.4 兼容性选择与 P0 整体尚未通过。

## 范围与路线

`Prototypes/PreviewProbe/` 是独立 Loomex 身份的 AppKit 实验，只有控制面板、一个固定内容样本和预览面板。点击“打开预览面板”只显示图标；点击“捕获一次”才预检权限。未授权时不会调用 `SCShareableContent` 或截图 API，也不循环弹权限提示。只有明确的“申请屏幕录制权限”按钮调用系统申请。

截图时从系统返回结果中按本进程 PID 和当前样本 `NSWindow.windowNumber` 精确匹配，再以 `desktopIndependentWindow` 过滤器捕获该窗口。不捕获显示器、其他应用或子窗口，不使用全局输入监听或辅助功能。图片只用于内存显示，不写文件，不上传；报告只保存技术状态和计数，不保存窗口列表、标题、截图或系统错误描述。

固定 AltTab v11.10.1 / `c500294bdb01186011a5c64a412b04cef9931bef` 的 `WindowThumbnails.swift` 第 170–177 行实际在 macOS 26+ 选择 ScreenCaptureKit，旧系统走 `CGSHWCaptureWindowList`；`WindowCaptureEvents.swift` 第 228–256 行说明普通窗口采用 `captureScreenshot`，避免逐次启动短流的开销。这是上游实现的取舍及注释证据，并非 Loomex 已复现实测旧系统故障。本轮不复制这些上游源码。

| 环境 | 本原型行为 | 实测边界 |
| --- | --- | --- |
| macOS 26+，SDK 26+ 编译 | 单次 `SCScreenshotManager.captureScreenshot`，SDR，不显示鼠标，不包含子窗口 | 本机 macOS 27.0 / Xcode 27.2 已获准捕获固定自建样本一次；其他系统未验证 |
| macOS 13–25 | 图标模式，保持样本选择 | 可按 macOS 13 部署目标编译；未在这些系统真实运行 |
| SDK 低于 26 | 编译图标路径，不引用 SDK 中不存在的新类型 | 构建脚本按实际 SDK 选择 `LOOMEX_SCREENSHOT_API`；不把编译通过当截图通过 |
| 未授权、样本关闭/最小化/隐藏、超时或截图失败 | 图标/状态提示，不阻塞样本选择 | 无权限路径已实际运行；其他系统截图路径逐项待测 |

13/14+ 的捕获路线尚未完成选择：本切片先证明本机公共 API 路径及降级边界，保留旧系统图标模式；上游私有捕获接口、14/15 公共接口替代、Space/全屏/多屏仍需独立验证。没有开始抽离 AltTab 窗口引擎或迁移原启动台。

## 生命周期与容量

`PreviewCaptureState` 只在主线程使用。每次面板打开和请求都带有逻辑代次，回调返回主线程后校验。收起面板、选择样本、关闭/最小化样本、应用隐藏，以及睡眠/屏幕睡眠/会话失活通知会释放显示图片并使旧结果失效。迟到的结果不能重新填充已收起或重新打开的面板。

后续生命周期切片补充了应用失去前台时的收起释放。菜单新增“显示样本窗口”⌘2、“隐藏本原型”⌘H；⌘1 显示控制面板并显式取消隐藏，不自动捕获。

- 最多一个系统请求链在途，无等待队列，无自动重试，无周期或后台捕获。
- 5 秒仅为逻辑超时；不能强制取消已提交的系统调用。超时/收起后保留在途槽，直到真实回调返回，才允许新请求。发现阶段迟到时直接丢弃，不再发起截图。
- 最多保留一张 `640 × 400` 内的缩略图，像素尺寸保持比例、不放大小窗口，图片预算 2 MiB；超界结果拒收。
- 已提交的请求可能仍短暂占用系统资源；面板收起不会被报告成“底层已取消”。原型无 `SCStream`，无需启动持续录制。

## 后续生命周期检查

该切片增加 `sampleExists`、`sampleMiniaturized`、`applicationActive`、`applicationHidden` 和 `displayImagePresent` 脱敏状态。它们是事件发生或界面刷新时的快照；`displayImagePresent` 在图标模式也为 true，只有收起时为 false 才表示图像视图没有持有图片或图标。

| 场景 | 本轮证据 |
| --- | --- |
| 截图后选择样本 | 请求/完成 1/1，选择计数 1，样本 key，预览收起，缓存及图像视图释放 |
| 截图后最小化样本 | 请求/完成 2/2，最小化为 true，缓存 0、在途 0、图像视图为空 |
| 最小化时再次捕获 | `target_unavailable`，请求数保持 2，保留图标；未发起额外截图 |
| 图标模式选择恢复 | 选择计数 2，样本恢复且 key，缓存 0，无自动捕获 |
| 截图后关闭样本 | 请求/完成 3/3，`sampleExists=false`，预览及图像视图释放 |
| 重建样本并重新捕获 | 请求/完成 4/4，560×352、811,008 字节，预览重新就绪 |
| 应用失去前台 | 清理代码已添加，等待真实前台切换；后台菜单与自动化快捷键未使本机应用失去前台，不计作通过 |
| 隐藏后显式恢复 | 菜单已添加；为保留上一项的待测界面，尚未执行 |

本轮重建临时签名后，系统设置条目仍为 on，但原型预检为 false。沿用已批准的同一应用录屏范围，添加当前构建并按系统提示退出重开后预检通过；这次签名记录刷新不代表“已显示预览时撤销授权”的故障处理已验证。原始状态保存在 `.local-data/p0/preview-lifecycle-*.json`，不提交截图或报告。

以上截图均已完成后才触发相应窗口动作；没有把它们称作真实系统请求在途时的关闭或迟到回调测试。
