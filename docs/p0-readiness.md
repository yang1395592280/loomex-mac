## 当前开发环境矩阵

| 环境或能力 | 当前结论 | 开发时的处理 |
| --- | --- | --- |
| Apple Silicon / macOS 27 / 单屏普通桌面 | 本机开发基线，自建样本已有证据；三模块产品闭环尚未实现 | 先在这一环境验证每个可运行切片 |
| macOS 26 | 新截图路线可以编译；没有实机结果 | 保留待测状态，不能从 API availability 推导支持 |
| macOS 13–25 | arm64 部署目标为 13；当前预览实现使用图标路径 | 保留代码路径，最低运行系统仍需实机验收 |
| Intel / Universal | 现有脚本只产出 arm64 | 独立排期，不发布 Intel 可用承诺 |
| Space / 全屏 / 多显示器 | 当前自建普通窗口结果无法覆盖 | 进入 Switch/Dock 集成后逐项验证与公布范围 |
| Finder / 浏览器 / Electron / 微信 / 模态窗口 | 未由本轮自建样本代替测试 | 真实应用矩阵是相关模块启用前的验收项 |
| 录屏撤销、睡眠与锁屏 | 部分失效规则有纯状态测试，真实行为尚未覆盖 | 保留未测项，系统权限故障实测需针对性授权 |

该矩阵是开发事实与验收计划，尚未接入产品设置或运行时能力开关。macOS 13 构建目标保持原样；最低发行版本待实机证据决定。本轮不引入旧系统私有截图接口。

## 架构复核结论

- 继续采用 Swift/AppKit 核心、SwiftUI 设置与单进程模块化。当前固定自建预览的约 30 MiB footprint 不足以证明组合应用资源预算，也没有形成必须增加 helper 的证据。
- Switch 与 Dock 的长期窗口发现、身份、MRU、动作和预览仍由同一个 AltTab 适配服务承载。隔离原型中的自身 AppKit 动作、Fixture AX 控制器和单样本捕获仅用于实验，不直接扩展为第二套产品窗口引擎。
- 预览保持按需、有界、无权限可用图标的设计。将单在途、逻辑失效与视图释放规则带入适配验收；不能把逻辑超时表述为已取消底层系统调用。
- 保留原启动台构建入口与布局格式。源码整合前继续记录上游版本、版权和修改，尚不进行大规模 AltTab 源码抽离。

以上复核维持既定技术路线，没有把原型通过等同于通用后端完成。

## 可独立推进的下一切片

Launch 应用骨架依赖现有启动台，不依赖尚未集成的跨应用窗口后端，可以先作为独立准备工作推进，同时继续维护 P0 缺口。

1. 建立 Loomex 的 Xcode 应用 target 和唯一入口，菜单栏仅装配 Launch；原 `build.py` 的独立启动台仍可构建。
2. 在现有 `Sources/main.swift`、`Interface.swift`、`Model.swift` 边界上小步引入 Launch 生命周期适配，保留布局与交互语义，复跑 59 项测试。
3. 新骨架使用隔离支持目录验证；尚不自动导入旧布局，也不与原程序共同写入同一文件。布局迁移作为后续独立任务。
4. Switch/Dock 展示尚未集成的状态，不注册快捷键、事件 tap 或申请它们的权限。接入前逐项关闭上表中的相关门禁缺口。

下一切片通过条件是一个可启动、可退出、可显示/收起 Launch 的 Loomex 应用和真实回归证据；不以占位设置或空协议声称三模块已整合。
