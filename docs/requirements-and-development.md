# Loomex Flow 整体需求与开发方案

日期：2026-11-07。版本：需求草案 0.1。状态：需求与开发方案已编写，功能整合尚未开始。

技术设计见 [技术选型与整体架构](technical-architecture.md)。现有代码和功能完成情况以 [README](../README.md) 为准，本文件的新增需求不能视为已实现。

## 1. 项目目标、来源和边界

| 项目 | 定义 |
| --- | --- |
| 发起人与初始使用者 | Loomex 品牌持有人及当前项目用户；后续面向需要经典启动台、逐窗口切换和 Dock 收起行为的 Mac 用户 |
| 用户已经明确的需求 | 整合 ClassicLaunchpad、基于 GitHub AltTab 的窗口切换、Dock 点击隐藏/最小化；整套开源并接受 GPL；使用 GitHub 管理源码 |
| 当前具体使用场景 | 从应用网格启动程序，使用 Alt+Tab 在具体窗口间选择，再通过 Dock 点击收起或恢复当前应用/窗口 |
| 需要解决的问题 | 用户希望在一个 Loomex 工具中配置这些交互；分别使用独立软件会形成不同入口、权限引导和设置方式 |
| 不整合的代价 | 继续分别安装和设置多个工具，无法由一个产品统一交互与状态；没有用户数量、节省时长或收入数据，不虚构 ROI |
| 更轻的可行方案 | 独立运行 ClassicLaunchpad、AltTab 和 Dock 工具能提供单项能力，但不满足“统一为一个 Loomex 产品”的目标 |
| 完成判据 | 安装一个应用，三项能力按需启用；共享设置与权限说明；正常路径、失败降级、数据保护和退出恢复均可验收 |
| 团队与资源假设 | 按个人或小团队持续迭代设计；团队经验与可投入时间尚未量化，估时仅作初步参考 |

首版范围：经典启动台、逐窗口切换、Dock 点击隐藏应用/最小化当前窗口/恢复、统一控制中心、旧布局导入、日志诊断、构建与分发。

后续范围：Dock 悬停预览、按应用覆盖动作、窗口平铺、Intel/Universal 支持、通过验证的更多 Space/全屏策略。云同步、账号体系、剪贴板、系统清理和跨平台版本不进入本轮开发。

本次交付范围是技术选型和需求方案；第三方源码导入、系统权限调整、布局实际迁移和正式发布将在对应开发任务执行。

## 2. 产品形态、默认值和界面

产品名 Loomex Flow，仓库名 loomex-mac。一个 `.app`，统一菜单栏和设置窗口；可选择在系统 Dock 保留 Loomex 图标。点击自身 Dock 图标打开 Launch，自身不参与 Dock 收起规则。

| 设置 | 推荐默认值 | 说明 |
| --- | --- | --- |
| Launch | 开启 | 无需先开启窗口控制权限 |
| Switch / Dock | 引导中由用户选择启用 | 未启用时不安装相关拦截；开启后按需申请权限 |
| Switch 快捷键 | Option+Tab，Option+Shift+Tab 逆向 | Command+Tab 保留系统行为 |
| Switch 范围 | 当前桌面优先 | 所有 Space、全屏和多屏支持按验证矩阵逐项公布 |
| Switch 预览 | 可选；授权后显示 | 拒绝屏幕录制后使用图标及可取得的标题 |
| Launch 全局快捷键 | 初始不绑定，由用户设置 | 菜单栏与自身 Dock 图标始终提供入口 |
| Dock 动作 | 隐藏整个应用 | 可改为最小化当前窗口，界面解释两者作用范围 |
| Dock 排除项 | Loomex 自身；Finder 初始排除 | 自身固定排除；Finder 首版保持系统行为 |
| 登录启动 | 关闭 | 用户主动开启后查询系统真实状态 |
| 更新 | 提供手动检查入口 | 自动检查需提供明确开关；发布服务就绪后才启用实际检查 |

统一设置建议包含：概览、启动台、窗口切换、Dock 增强、快捷键与应用排除、权限、通用与更新、关于与开源许可。首版以原生设置风格和清晰状态为主。

快捷键作用域：Launch 活动时保留现有 ⌘, 启动台快捷选项；其他适用界面可用 ⌘, 打开统一设置。菜单栏始终提供统一设置入口。

### 3.4 Dock 点击增强

| ID | 优先级 / 类型 | 场景与必须满足的行为 | 验收证据 |
| --- | --- | --- | --- |
| FR-DOCK-01 | P0 新增 | 点击前应用未运行时正常启动；已运行但不是前台应用时正常激活；第一次点过去不能立即被收起 | 未运行/后台/前台三种点击前状态验证 |
| FR-DOCK-02 | P0 新增 | 当前应用有普通窗口且模式为隐藏应用时，再次点击隐藏该应用所有可隐藏窗口；再次点该应用正常恢复显示 | 多窗口应用显隐测试 |
| FR-DOCK-03 | P0 新增 | 模式为最小化当前窗口时，只最小化点击前的目标普通窗口；其他窗口不被批量最小化；不可最小化窗口保持安全结果 | 多窗口、模态、全屏与不可操作目标验证 |
| FR-DOCK-04 | P0 新增 | 对 Loomex 本次会话收起的窗口可恢复；不额外恢复用户此前主动最小化的其他窗口；窗口关闭/应用重启使旧恢复记录失效 | 人工最小化与 Loomex 最小化混合测试 |
| FR-DOCK-05 | P0 新增 | 排除的应用、Finder 初始排除项和 Loomex 自身不触发增强；自身图标继续打开 Launch；用户新增排除立即生效 | 默认排除与自定义排除验证 |
| FR-DOCK-06 | P0 新增 | Dock 图标重排拖动、右键、修饰键点击、文件夹/废纸篓等非目标操作保留系统行为；主单击序列不遗留按键状态 | 按下/抬起、短拖、重排和特殊项目验证 |
| FR-DOCK-07 | P0 新增 | Dock 重启、位置改变、自动隐藏、放大、显示器变化后重新识别图标；无普通窗口的应用保留系统新建/重新打开行为；权限失效后停止拦截 | Dock 状态变化、无窗口和授权撤销测试 |

Dock 规则基于点击前的前台状态，而非系统激活后的状态。一次操作不自动退出应用、不批量恢复全部历史最小化窗口。连续快速点击与多击属于原型阶段必须定下策略的边界，需验证事件序列后在开发记录中明确去重/节流规则。

最小化全部窗口、按应用覆盖动作和 Dock 悬停预览为 P2；v1.0 只提供全局动作模式与应用排除。

## 4. 关键用户流程

### 初次使用

打开应用 → 了解三项能力 → 选择模块 → 仅为所选能力说明并请求权限 → 可选导入旧布局 → 菜单栏常驻。拒绝辅助功能不影响 Launch，拒绝屏幕录制不阻断允许的无预览 Switch 模式。

### 应用与窗口操作闭环

打开 Launch → 搜索并启动应用 → Option+Tab 选择具体窗口 → 点击当前应用的 Dock 图标收起 → 再点击恢复。每个动作都应由同一套应用/窗口身份和焦点协调规则解释。

### 暂停、故障和退出

全局暂停 → 拦截停止，原系统操作可继续 → 恢复时重查权限与窗口快照。权限被撤销或后端失效时只暂停依赖能力。退出时清理监听与覆盖窗，不因退出操作修改用户窗口布局。

## 5. 非功能要求与测量方式

以下数字是建议的初始预算，尚非实测结果。P0 必须记录基准 Mac 型号、内存、系统、分辨率和软件样本，复核预算后作为实现验收基线。

统一场景：200 个应用、20 个普通窗口；面板预热 5 次后采集至少 100 次交互，另记录冷启动。标题、截图或其他隐私内容不进入公开测量结果。

| ID | 初始要求 | 验证方式 |
| --- | --- | --- |
| NFR-01 交互延迟 | 预热后 Launch 首个可交互内容 P95 ≤250ms；Switch 图标候选内容 P95 ≤150ms；缩略图异步补齐 | 应用收到触发到内容提交显示的埋点；与真实交互录像对照，不冒充 GPU 呈现延迟 |
| NFR-02 空闲资源 | 面板收起并稳定 60 秒后，CPU 时间/墙钟时间的单核占用均值 <1%；组合应用 physical footprint 起始预算 ≤150MiB | 同一条件采样 CPU 时间与 vmmap physical footprint；不以 RSS 代替 footprint |
| NFR-03 缓存与释放 | 面板隐藏后停止非必要捕获；重复开关 50 次无持续无界增长；缓存有明确字节/数量上限 | 捕获任务计数、缓存计数、分阶段内存采样 |
| NFR-04 可恢复性 | 切换目标失效、AX 超时、Dock 重启和权限撤销后不阻塞 UI；可取消面板或暂停相关模块 | 故障场景集及实际操作；系统调用超时不宣称能强制取消底层调用 |
| NFR-05 数据保护 | 导入和配置写入失败不覆盖有效旧数据；运行状态和缩略图不作为长期布局内容保存 | 文件前后校验、异常注入与备份恢复 |
| NFR-06 可访问性与语言 | 支持键盘操作、中文/英文文案、原生中文输入及 VoiceOver 基本标签；保留用户选择是否跟随系统减弱动态效果的偏好，尊重减弱透明度设置 | 原生输入、键盘、VoiceOver 和系统显示设置检查 |
| NFR-07 隐私 | 默认本地处理，不上传应用使用记录、窗口标题或截图；诊断导出可预览范围 | 网络行为与日志内容检查 |
| NFR-08 可追溯构建 | 固定第三方版本；每次发布关联源码标签、构建号、依赖清单和校验结果 | CI、签名与源码下载复现记录 |

“动画流畅”不以显示同步回调频率证明；需要结合 Instruments、实际交互和目标显示器观察。阶段 0 后如需改变预算，应记录样本与原因，不能为了通过测试静默放宽。

| Dock | 底部/左侧/右侧、自动隐藏、放大、重启 | 任一位置的命中问题必须修复或明确关闭对应能力 |
| 应用 | Finder、Safari、Chrome、至少一款 Electron 应用、微信、原生 AppKit 应用 | 特殊窗口通过能力判定与应用排除处理 |
| 窗口 | 普通、多窗口、隐藏、最小化、无窗口、全屏、模态、窗口关闭/重建 | 受保护预览与系统不可控窗口使用明确降级 |
| 权限 | 未授予、已授予、撤销、重新授予 | 不循环弹窗，不用配置值伪装授权状态 |
| 生命周期 | 手动启动、登录启动、睡眠唤醒、锁屏/解锁、退出与重开 | 捕获和恢复记录必须正确失效或重建 |

## 9. 发布、回退与维护

开发与测试使用隔离支持目录；发布从带版本标签的提交构建，生成应用、DMG、校验清单、源码与发行说明。生产签名、公证凭据不进入代码仓库。

应用升级前保留程序回退入口，涉及配置 schema 变化时备份对应数据；回退必须同时考虑旧程序能否读取新配置，不能只替换二进制。首次导入旧启动台始终保留原目录，以便回到独立旧程序。

运行诊断记录模块有效状态、失败类型、耗时和资源计数。默认不建立服务端遥测；用户可主动导出脱敏诊断。系统大版本发布前后复核 AX、事件拦截、窗口预览与私有 API 关键路径。

按版本维护：支持矩阵、上游锁定版本、第三方许可、已知限制与回退说明。出现兼容性故障时优先暂停有问题的增强模块，再通过补丁或明确的支持范围调整恢复。
